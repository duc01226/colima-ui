# Frontend patterns

> Last scanned: 2026-10-14

Read this before changing Svelte views, stores, API calls, forms or navigation. It records current source patterns; use the cited owner when changing a contract. Source inspection does not establish runtime or accessibility conformance.

## Composition and navigation

The HTML entry mounts one Svelte application. Views use typed `$props`, callback props, rune state and, where two-way ownership is needed, `$bindable`. Content wrappers take `Snippet` children rather than a base-component hierarchy (`src/main.ts:12`, `src/components/RowActions.svelte:27`, `src/components/settings/SettingsSection.svelte:8`, `src/components/settings/SettingsSection.svelte:29`).

`App.svelte` statically imports pages and selects them through `uiState.currentPage`, restored from localStorage. Ordinary views unmount on navigation and are keyed by Windows origin generation after host/ready/resource admission; stale details cannot survive loss/recovery. Settings/Help/Terminal have independent admission, and Terminal delays first mount then hides the same instance to preserve its sessions (`src/App.svelte:80`, `src/App.svelte:230`, `src/App.svelte:122`, `src/App.svelte:284`). This is page state, not a URL router or lazy module loading.

Sidebar ordinary items select a page, while AI chat toggles a side panel. Graph/list handoffs set resource intent before navigation; Topology, Containers and Compose consume matching focus requests only while their destination is mounted; late read completion cannot consume a newer shared focus/Logs request. Preserve the target's resource-identity conversion and read `docs/topology-design-philosophy.md` when changing those flows (`src/components/Sidebar.svelte:402`, `src/lib/topology-link.ts:23`, `src/components/topology/NodeDetail.svelte:84`, `src/pages/Topology.svelte:82`, `src/pages/Containers.svelte:137`, `src/pages/Compose.svelte:58`). Keyboard navigation excludes editable inputs; xterm is excluded before global Escape/editor handling (`src/lib/keyboardShortcuts.ts:25`).

## State, requests and events

Dashboard separately owns engine-resource and Compose-count reads. It checks mount lifetime and known host before publishing; Windows results must match the captured, active-ready and loaded generation. A recovered mount fetches current figures despite the usual cache interval. Its Windows Compose count shows loading or an attributed failure until a current successful read supplies a number, including a genuine zero; supported-platform cache behavior remains separate. VM/Kubernetes acquisition and controls use the existing host policy; unavailable Windows resources do not become VM allocation zeros (`src/pages/Dashboard.svelte:21`, `src/pages/Dashboard.svelte:94`, `src/pages/Dashboard.svelte:153`, `src/pages/Dashboard.svelte:278`).

Module-scoped rune objects own shared Docker/resource/dashboard/navigation data; pages own filters, selection and operation state. `instancesLoaded` distinguishes an unknown cold-start list from loaded-empty. Kubernetes has its own connectivity and list-loading state (`src/store.svelte.ts:3`, `src/store.svelte.ts:20`, `src/store/k8s.svelte.ts:42`, `src/pages/Containers.svelte:31`).

`src/lib/api.ts` is a compatibility re-export; typed wrappers live under `src/lib/api/`. Ordinary `call<T>` selects native IPC or localhost HTTP. Native SSE consumers resolve only this instance’s bound `api_port` via IPC; an unbound/invalid answer fails without health fallback. Browser development keeps the 11420–11429 health discovery. Bearer/query-token rules and response unwrapping remain separate from stream behavior (`src/lib/api/client.ts:45`, `src/lib/api/client.ts:112`, `src-tauri/src/api_server.rs:34`).

API list mapping and event mapping have separate owners. Docker list wrappers normalize their own results; push updates use `normalizers.ts` through the data poller. Trace both when changing a field (`src/lib/api/docker.ts:7`, `src/lib/normalizers.ts:12`, `src/lib/dataPoller.ts:167`).

The data poller owns run/revision/disposal and the shared Windows refetch publication predicate. Refetch fulfillment and rejection must match the current ready generation; the four resource-page writers and retained Terminal picker delegate to it on Windows. Native Windows container/image events update only those families and cannot clear an aggregate read failure. A complete current four-family refresh owns recovery. The shared store records that complete generation separately from C/I provenance; App waits for both before ordinary-view admission and one-shot draft restoration. Loss clears the completeness marker, and a newer generation must establish its own complete read; Terminal retains its independent C/I targeting. Delayed volume/network acquisition, data and errors match both the captured event generation and the latest complete-refresh outcome revision, so an older pair cannot overwrite a newer same-generation success or failure. Current Windows pair rejection is attributed through the shared error state. Native POSIX and browser refreshes publish successful C/I, volume and network groups independently and retain failed groups while retrying; each publication still checks run/revision ownership. Their delayed volume/network reads publish independently too. Its loss path keeps already-mounted volume/network views loading through failed delayed reads, even while capabilities retain a running snapshot. Known macOS/Linux VM views remain reachable when Docker reads fail, including with a retained Docker error; they do not inherit the Windows aggregate admission gate. Native late listener acquisition releases after disposal; browser SSE backoff/polling and metrics discovery retain their own teardown (`src/lib/dataPoller.ts:31`, `src/lib/dataPoller.ts:89`, `src/lib/dataPoller.ts:167`, `src/pages/Terminal.svelte:66`, `src/lib/api/metrics.ts:65`).

Transfers outlive their dialog. The app owns the session subscription; events provide quick updates, while `transferApi.list()` reconciles authoritative state after connection/gaps. Keep transport adaptation outside the notification store. Unknown old jobs become an explicit ended outcome, not inferred success (`src/App.svelte:160`, `src/components/transfer/TransferDialog.svelte:191`, `src/lib/transferEvents.ts:13`, `src/lib/transferNotifications.ts:62`, `src/store/notifications.svelte.ts:357`).

`reportError` is the intended operation-error presentation owner, with normalization, localization, remediation and session history. Existing owners also use local indicators or direct toasts; this is not proof that every thrown error follows one path (`src/lib/errorReporter.ts:1`, `src/pages/Containers.svelte:196`, `src/pages/Security.svelte:78`). Capability helpers distinguish missing/stopped tools from genuinely empty lists (`src/store/capabilities.svelte.ts:63`).

Host capability policy governs page acquisition, event catalogs and notices; an unknown platform cannot authorize VM/Kubernetes work. Windows setup/settings/sidebar/tour and Compose use that policy rather than treating Docker as dependent on Colima (`src/store/capabilities.svelte.ts:147`, `src/store/capabilities.svelte.ts:149`, `src/components/SetupWizard.svelte:298`, `src/pages/Compose.svelte:30`).

## Form and lifetime variants

Image export recovery binds every content-ID/reference pair to fresh images. The nested TransferDialog also matches mode/container/reference/content signature before restoring paths and overwrite. Starting still sends ordinary image references; recovery neither freezes tags nor starts work (`src/pages/Images.svelte:34`, `src/components/transfer/TransferDialog.svelte:52`, `src/components/transfer/TransferDialog.svelte:176`).

| Owner | Validation, failure and persistence contract |
| --- | --- |
| Network/volume creation | Trimmed-name action checks; submit is disabled while busy or empty. Reset fields on success, retain them after request failure and report via toast (`src/pages/Networks.svelte:77`, `src/pages/Networks.svelte:255`, `src/pages/Volumes.svelte:76`). |
| Image pull | Pending/rejected input stays editable; duplicate form submission is refused while pending. Only a successful submission matching the current edit revision clears the form. Expected UI failures remain in the form/toast path; automation overrides preserve user input and propagate their own failure (`src/pages/Images.svelte:92`). |
| Engine connection | Shared Setup/Settings form keeps active status, candidate check and persisted next launch distinct. Stale checks are discarded; save failure retains input. | Colima configuration | Preview on `change`, show field-coded issues after controls, send only changed fields and preserve the loaded mtime contract. Refused apply retains input (`src/pages/settings/ColimaConfig.svelte:123`, `src/pages/settings/ColimaConfig.svelte:161`, `src/pages/settings/ColimaConfig.svelte:181`, `src/pages/settings/ColimaConfig.svelte:355`, `src/pages/settings/ColimaConfig.svelte:426`). |
| Transfer start | Required-field gate and in-place start error retain editability; accepted start hands over the job and closes (`src/components/transfer/TransferDialog.svelte:191`, `src/components/transfer/TransferDialog.svelte:204`, `src/components/transfer/TransferDialog.svelte:210`, `src/components/transfer/TransferDialog.svelte:308`). |
| Model/provider settings | Model free text is deliberate and commits per keystroke; provider-specific keys/endpoints/models have separate ownership. Settings writes update local state first and log persistence failures (`src/components/settings/ModelPicker.svelte:5`, `src/components/settings/ModelPicker.svelte:81`, `src/components/settings/AIPanelSettings.svelte:32`, `src/lib/settingsStore.svelte.ts:47`). |

Ordinary Windows resource pages unmount while unavailable. App owns one memory-only active-page/original-origin recovery scope; generation is a revision. Registered snapshots retain unsent fields plus neutral checked IDs, filters and detail/tab preferences once, resolving identities against fresh resources/graph/samples/project lists. Navigation, origin change and App disposal discard them; old results, callbacks, approval/busy state and effect replay are excluded (`src/App.svelte:86`, `src/lib/recoveryDrafts.svelte.ts:17`, `src/pages/Containers.svelte:504`, `src/pages/Topology.svelte:49`, `src/pages/Activity.svelte:55`, `src/pages/Compose.svelte:26`).

Activity owns its nested action-kind preference; Security owns severity/passed choices through bound child props and restores image-specific choices only for matching content ID plus reference. Fresh detail reads can restore presentation, while diagnosis, scan and export still require an explicit action. Terminal retains its own sessions; unknown host policy cannot acquire/present Docker targets (`src/pages/Activity.svelte:288`, `src/pages/Security.svelte:67`, `src/pages/Security.svelte:449`, `src/pages/Terminal.svelte:59`).

The resource owner performs teardown through returned mount/effect cleanup or `onDestroy`, including acquisitions that finish late. App owns poller/transfer subscriptions; their native adapters release late listeners, while TerminalInstance closes a late session handle (`src/App.svelte:164`, `src/lib/dataPoller.ts:261`, `src/lib/transferEvents.ts:76`, `src/pages/TerminalInstance.svelte:137`). Preserve each owner’s run/disposal guard rather than inferring universal cleanup.

TerminalInstance shows container/engine plus Connecting/Connected/Ended/error state, disables ended input and carries original target metadata to explicit Logs recovery. It closes a handle acquired after unmount and never replays commands automatically. xterm owns shell keys; Ctrl+Shift+F6 returns focus to session controls, and Focus terminal restores input focus. screenReaderMode/accessible names do not certify native assistive behavior (`src/pages/TerminalInstance.svelte:40`, `src/pages/TerminalInstance.svelte:95`, `src/pages/TerminalInstance.svelte:107`, `src/pages/TerminalInstance.svelte:130`, `src/pages/TerminalInstance.svelte:209`).
