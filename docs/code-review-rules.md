# Project code review rules

> Last scanned: 2026-10-14

Read this before reviewing changes. Start at the actual rule owner and its consumers; distinguish executable gates, documented intent and observed variants. The checks below are source-backed guidance, not a claim that the current application passed a runtime audit.

## Backend contracts to preserve

- Trace HTTP, IPC and direct CLI/service callers together. Shared commands own exec/run guards, but direct-route and adapter paths exist. HTTP Colima stop/delete do not perform all native state cleanup/activity effects (`src-tauri/src/commands/containers.rs:839`, `src-tauri/src/routes/k8s.rs:15`, `src-tauri/src/routes/instances.rs:28`, `src-tauri/src/commands/colima.rs:330`).
- Preserve public health/protected operations and the explicit query-token allowlist; retain desktop IPC/browser-fragment token handoff and the absence of an HTTP token endpoint. Auth tests protect the router/token rules (`src-tauri/src/api_server.rs:356`, `src-tauri/src/api_server.rs:568`, `src-tauri/src/api_server.rs:678`, `src-tauri/src/auth.rs:15`, `src-tauri/src/auth.rs:49`, `src-tauri/src/auth.rs:203`, `src/lib/api/client.ts:223`).
- Keep app and CLI data resolution at the shared platform owner: Windows uses native KnownFolder LocalAppData plus `ColimaUI`; macOS/Linux retain their existing HOME or `/tmp` plus `.colima-ui`. Preserve native PATH split/join and absolute `.exe` discovery; Windows host-probe failures remain errors (`src-tauri/src/path_util.rs:76`, `src-tauri/src/path_util.rs:102`, `src-tauri/src/path_util.rs:240`, `src-tauri/src/windows_host.rs:38`, `src-tauri/src/commands/system.rs:413`).
- Preserve exact-instance CLI handoff: supersede the nonsecret settings marker before bind, publish only an owner-private reference after bind, and never fall back to another health port. Establish privacy before bytes and verify the opened handle; failed publication leaves in-app access available. Cleanup removes only its own record and prevents late publication. Native Windows ordinary-account denial still needs qualification (`src-tauri/src/api_reference.rs:72`, `src-tauri/src/api_reference.rs:93`, `src-tauri/src/api_reference.rs:108`, `src-tauri/src/api_reference.rs:125`, `src-tauri/src/private_file.rs:8`, `src-tauri/src/private_file.rs:225`, `src-tauri/src/api_server.rs:417`).
- Preserve the captured Windows context/pipe/executable/config and controlled Docker environment/global selectors. Saved preferences cannot retarget a resolved connection; failed selection cannot authorize another engine. Require original Linux daemon identity, ordered overlapping checks and current read generation (`src-tauri/src/engine_connection.rs:20`, `src-tauri/src/engine_connection.rs:55`, `src-tauri/src/engine_connection.rs:136`, `src-tauri/src/engine_connection.rs:194`, `src-tauri/src/engine_connection.rs:354`).
- Keep SDK unavailable/partial snapshots distinct from successful empty results and scope CPU history by origin/recovery generation. Preserve one daemon event stream; SSE consumes raw events. Generic child-process ownership must precede Windows child execution and retain bounded capture/deadlines without resource-domain fields (`src-tauri/src/docker_state.rs:466`, `src-tauri/src/sse.rs:151`, `src-tauri/src/commands/metrics_collector.rs:372`, `src-tauri/src/child_process.rs:86`, `src-tauri/src/child_process.rs:159`, `src-tauri/src/child_process.rs:387`).
- Preserve stable error-code serialization, redacted technical/command context and frontend localization ownership. Keep profile/default-name and caller-selected-base path-confinement semantics; typed shell text is a different guard (`src-tauri/src/error.rs:22`, `src-tauri/src/error.rs:303`, `src-tauri/src/error.rs:320`, `src-tauri/src/error.rs:342`, `src-tauri/src/validation.rs:167`, `src-tauri/src/validation.rs:303`, `src-tauri/src/validation.rs:406`).
- Covered mutations record actual outcomes without secrets. Update the named activity contract lists when extending them; these sensors do not discover every future command. Preserve failure reason and shared self-heal verb spelling (`src-tauri/src/commands/activity_coverage.rs:42`, `src-tauri/tests/activity_records_every_mutating_command.rs:29`, `src-tauri/src/commands/activity.rs:589`, `src-tauri/src/commands/activity_coverage.rs:161`).
- Self-heal must retain advisory-only actions, Suggest fallback, kill-switch-before-action, quota outcome accounting and crash-window reset (`src-tauri/src/commands/self_heal.rs:607`, `src-tauri/src/commands/self_heal.rs:1151`, `src-tauri/src/commands/self_heal.rs:1116`, `src-tauri/src/commands/self_heal.rs:1124`, `src-tauri/src/commands/self_heal.rs:1151`).
- Preserve unknown Colima YAML keys/expected-mtime refusal and distinguish a SQLite lock from a transaction. File-output transfer success follows scratch publication under the caller’s overwrite policy; cancellation intent precedes kill. Lossy channels require the owner's recovery strategy (`src-tauri/src/commands/colima_config.rs:605`, `src-tauri/src/commands/colima_config.rs:798`, `src-tauri/src/commands/ai_chat.rs:183`, `src-tauri/src/commands/activity.rs:424`, `src-tauri/src/commands/file_transfer.rs:419`, `src-tauri/src/commands/file_transfer.rs:866`, `src-tauri/src/streaming_cmd.rs:441`, `src-tauri/src/routes/misc.rs:83`).

Read `docs/backend-patterns-reference.md` when reviewing request/storage/async changes and `docs/domain-entities-reference.md` when reviewing identity or lifecycle rules. `runtime::run` uses owned bounded capture; audit other timeout/stream/PTY paths separately. Check `host_features` at raw HTTP, command/adapter and tool boundaries; native API origins must come from `api_port` without health fallback. Connection save must remain pending-only, and restart must pass atomic admission/cleanup before request. Safe-only command SSE cannot grant approval; event advertisement, actual outgoing model context, legacy acquisitions and self-heal generations each have separate owners (`src-tauri/src/host_features.rs:74`, `src/lib/api/client.ts:45`, `src-tauri/src/commands/engine_connection.rs:72`, `src-tauri/src/routes/kb.rs:98`, `src/lib/agentCore.ts:77`, `src-tauri/src/commands/self_heal.rs:679`). Read `plans/261014-1121-windows-docker-ui/plan.md` for final entry-point/native qualification; authored source is not complete executing proof. Native compiler/type checks do not qualify Windows behavior.

## Frontend contracts to preserve

SAFE configuration status is model-request content. Inspect its real handler-to-history sender path: known-provider/presence-only output and fixed unknown-status errors must exclude stored active/inactive keys, free-form models/endpoints and unrelated settings. Keep selected connection authentication separate (`src/lib/aiEvents/config.ts:47`, `src/lib/agentCore.ts:101`, `src/lib/agentCore-config.test.ts:40`).

- Reuse typed props/callbacks and matching shared owner contracts; feature actions stay with their owner. Page state is not a URL router, and Terminal has a deliberate retained mount lifetime (`src/components/RowActions.svelte:27`, `src/components/settings/SettingsSection.svelte:8`, `src/App.svelte:122`, `src/App.svelte:284`).
- Trace both API-list mapping and event normalization when changing a field. Runtime detection belongs to `env.ts`; ordinary requests use typed API wrappers. Metrics' SSE-in-both-modes contract is separate (`src/lib/env.ts:1`, `src/lib/api/client.ts:112`, `src/lib/api/docker.ts:7`, `src/lib/dataPoller.ts:167`, `src/lib/api/metrics.ts:65`).
- Preserve loading versus loaded-empty/capability distinctions, per-operation failure attribution, IME-safe send, and accepted-transfer handoff to app-lifetime notifications. Unknown expired outcomes must not become inferred success (`src/store.svelte.ts:20`, `src/store/capabilities.svelte.ts:63`, `src/lib/errorReporter.ts:23`, `src/components/AiChatPanel.svelte:133`, `src/components/transfer/TransferDialog.svelte:191`, `src/store/notifications.svelte.ts:357`).
- Check acquisition, publication and teardown at the actual owner. Data-poller run/revision/disposal and Windows origin fences must reject pre-loss reads/events, immediately release late listeners and clear stale detail intent. App ordinary-view admission/generation keys must preserve the separate retained Terminal owner (`src/lib/dataPoller.ts:28`, `src/lib/dataPoller.ts:71`, `src/lib/dataPoller.ts:261`, `src/App.svelte:230`, `src/App.svelte:284`).

Check the shared connection form’s active/candidate/saved-next distinction, retained failed draft, explicit restart/transfer refusal and Cancel focus return. Unknown host policy must not authorize VM/Kubernetes acquisition; unsupported/stopped/missing/empty states and Compose plugin readiness have different recovery. Native keyboard/NVDA/reflow/locale proof is separate from DOM fixtures and Svelte checks (`src/components/settings/EngineConnectionSettings.svelte:25`, `src/components/settings/EngineConnectionSettings.svelte:34`, `src/store/capabilities.svelte.ts:147`, `src/pages/Compose.svelte:30`).

For recovery/input changes, inspect real App/page/nested controls: retain neutral fields/IDs/filter/tab choices only within one page/original-origin scope, consume once and discard on navigation/origin/disposal. Bind selections to fresh identities; request new read output rather than old logs/processes/audits. Diagnosis/scan/export and effects still need explicit action. Check mounted state before asynchronous Containers/Topology/Compose callbacks consume shared focus or pending Logs. Parent-owned nested props must preserve preferences without retaining results or busy/callback/approval state. Failed/pending pulls and stale completion preserve the current draft; automation owns its outcome (`src/lib/recoveryDrafts.svelte.ts:17`, `src/pages/Containers.svelte:504`, `src/pages/Activity.svelte:288`, `src/pages/Security.svelte:449`, `src/App-recovery.test.ts:396`).

Trace every shared-resource writer, including retained Terminal: Windows page refreshes use the common publication predicate for fulfillment and rejection; preserve captured event generation at delayed-read admission and settlement. Unknown host policy refuses Terminal acquisition and Windows/unresolved assistant read failures cannot masquerade as healthy empty. Actual App-held refresh, held-generation rejection and outgoing-history controls are source-guard mappings; use current run evidence separately and do not infer whole-source/native acceptance (`src/lib/dataPoller.ts:31`, `src/lib/dataPoller.ts:167`, `src/pages/Terminal.svelte:66`, `src/lib/agentCore.ts:222`, `src/App-recovery.test.ts:571`, `src/lib/dataPoller.test.ts:207`, `src/lib/agentCore.test.ts:54`).

Read `docs/frontend-patterns-reference.md` for form/lifetime variants, `docs/design-system/README.md` for tokens/visual owners and `docs/topology-design-philosophy.md` before changing graph actions. Source observations describe their owner scope; do not promote one form's validation or draft retention to a universal policy.

For current native Windows failures, inspect the outcome as well as freshness: the Dashboard Compose card must distinguish pending/failed reads from a successful zero; a partial container/image event cannot clear an aggregate resource failure or certify first/full recovery. Inspect the separate full-read generation at poller/store and both ordinary admission/recovery scope consumers; only a successful current four-family result supplies membership for one-shot selection restoration. Preserve independent C/I provenance and Terminal targeting. Delayed volume/network acquisition, data and errors must not overwrite a newer complete-refresh outcome in the same generation. Assistant capability tests must use real registry definitions and the actual sender: syntax checks or substituted catalogs cannot prove advertised names execute. Preserve backend bans and supported-platform behavior. For macOS/Linux, Docker failure must leave VM-management Start controls reachable; full/event refresh must preserve successful independent groups and reject stale/disposed results. Check actual App/VM boundary and peer-failure assertions, beyond healthy resource-page controls. After actual loss, already-mounted volume/network pages must stay loading through failed delayed reads, including with cached running capabilities; genuine empty success must still clear loading (`src/pages/Dashboard.svelte:104`, `src/lib/dataPoller.ts:167`, `src/lib/aiEventBus.ts:26`, `src/lib/agentCore-config.test.ts:96`).

## Executable quality gates and limits

The dependency gate accepts only the pinned cargo-audit version in either direct-binary or Cargo-dispatched banner form. Keep exact finding-specific legacy exceptions, rationale/owner/review date and fail-on-new behavior. An exception is neither remediation nor distribution clearance; current legacy license/notice disposition remains a release prerequisite (`scripts/check-dependencies.mjs:9`, `scripts/windows-quality-baseline.json`).

Package gates include frontend lint/type/Svelte/token/i18n/Vitest, `npm run test:tooling`, `npm run check:windows` and locked all-target/all-feature Clippy with `-D warnings`. CI runs native library tests on macOS/Linux/hosted Windows and builds the standalone CLI; ignored provider tests remain explicit (`package.json:19`, `package.json:25`, `.github/workflows/ci.yml:143`). Foundation sensors check declared formatting, generic/domain dependency direction, exact credential-pattern exceptions and config/toolchain drift; dependency health separately requires fresh npm/RustSec/license metadata and exact reviewed exceptions (`scripts/check-windows-foundation.mjs:11`, `scripts/check-dependencies.mjs:9`). Source sensors and dependency reports do not establish native behavior.

The pre-push hook runs npm frontend/tooling/foundation gates and Clippy. Its explicit `SKIP_LINT_GATES` branch means hook presence is not proof a push ran checks. Package prepare uses platform-neutral Node with literal Git argv; installed hooks remain POSIX shell scripts, requiring Git for Windows on Windows (`.githooks/pre-push:12`, `.githooks/pre-push:30`, `scripts/setup-hooks.mjs:3`). Hook setup is separate from native qualification.

CSS-token checking catches undefined custom-property reads, with an exception for runtime column widths. Localization checking compares locale keys to English and recognizes a limited literal-call syntax; neither sensor validates rendered styles, accessibility or translation quality. ESLint ignores docs/framework/generated paths and intentionally disables some Svelte/a11y rules (`scripts/check-css-tokens.mjs:12`, `scripts/check-css-tokens.mjs:29`, `scripts/check-i18n-keys.mjs:55`, `scripts/check-i18n-keys.mjs:81`, `eslint.config.js:20`, `eslint.config.js:106`).

Keep the metrics collector independent from paid-build modules; a library source sensor pins that boundary (`src-tauri/src/commands/metrics_collector.rs:819`). Choose real boundary evidence deliberately: ignored tests and prerequisite early returns can produce green harness results without exercising Docker/Trivy. Read `docs/integration-test-reference.md` before selecting those commands (`src-tauri/tests/security_scan_against_trivy.rs:28`, `src-tauri/tests/security_score_against_corpus.rs:49`).

Review failures against the governing owner and actual consumers. Current references name regression guards and their limits; historical manual examples, source sensors and a successful exit alone do not establish full behavior coverage.

For Windows packaging, native provider fixtures, installed metrics, account/update controls, exact-byte mutation recovery and evidence limits, read `docs/windows-qualification.md`. Build receipts, hosted Server jobs and structural bundle validation each retain their own scope; Windows 11/both-provider/installed proof is required before release acceptance. Fault seeds require actual failed assertions and final-green restoration, not compiler failures (`scripts/fault-seed.mjs:59`, `scripts/windows-evidence.mjs:63`).
