# Resource concepts and ownership

> Last scanned: 2026-10-14

Read this before changing resource identity, lifecycle, safety rules or persisted application choices. Docker, Colima and Lima own live resources; application stores and histories are representations. The source establishes business rules without a required entity hierarchy or DDD layer model.

## Concepts and invariants

| Concept | Identity, authority and rule owner |
| --- | --- |
| Colima profile | Empty profile selects default at the guarded command boundary. Names affect both argv and paths. For command/tray start, existing `colima.yaml` wins over wizard defaults; resource flags are emitted only on first start. Separate VM adapter start constructs its own flags (`src-tauri/src/validation.rs:125`, `src-tauri/src/validation.rs:167`, `src-tauri/src/commands/colima.rs:119`, `src-tauri/src/commands/colima.rs:136`, `src-tauri/src/adapters/colima.rs:59`). |
| Container | Runtime-owned identity/state. Shared exec checks ID/text; shared run rejects prohibited flags/root-bind forms before execution and logs environment counts. Separate literal lifecycle/adapter paths have their own contracts (`src-tauri/src/commands/containers.rs:839`, `src-tauri/src/commands/containers.rs:904`, `src-tauri/src/commands/containers.rs:921`, `src-tauri/src/commands/containers.rs:978`). |
| Selected engine origin | A resolved Windows connection captures context/local pipe/executable/config for the process; original Linux daemon ID and availability generation authorize work. Active status, checked candidate and persisted next-launch preference are separate; saving does not retarget, and explicit restart must admit/settle owned work before creating a new session (`src-tauri/src/engine_connection.rs:20`, `src-tauri/src/engine_connection.rs:194`, `src-tauri/src/commands/engine_connection.rs:16`, `src/lib/engineConnection.svelte.ts:77`, `src-tauri/src/commands/engine_connection.rs:72`). Endpoint reuse alone is not daemon identity. |
| Transfer job | Registry-owned ID/status/destination claim, separate from OS process identity. Starting/Running → exactly one Success/Failed/Cancelled; cancelled/terminal jobs cannot run again or overwrite the first outcome. Atomic shutdown admission shares the registration lock (`src-tauri/src/transfer_registry.rs:194`, `src-tauri/src/transfer_registry.rs:216`, `src-tauri/src/transfer_registry.rs:184`). Cancellation can settle before spawn. File-output success follows publication; other jobs settle after successful process completion. Terminal entries remain readable for 60 seconds; state is not persisted across app exit (`src-tauri/src/transfer_registry.rs:35`, `src-tauri/src/transfer_registry.rs:123`, `src-tauri/src/transfer_registry.rs:193`, `src-tauri/src/commands/file_transfer.rs:351`, `src-tauri/src/commands/file_transfer.rs:382`, `src-tauri/src/commands/file_transfer.rs:419`, `src-tauri/src/streaming_cmd.rs:441`, `src-tauri/src/streaming_cmd.rs:553`). |
| Terminal session | UI ID keys one managed PTY; replacement closes its prior child. ContainerExec carries stable container ID/original engine; preflight and create require running/nonpaused state. Windows accepts Docker-container sessions only, uses ConPTY Job ownership and fences input after origin loss. The shared cap of 16 counts the union of live and opening IDs; one pending open per ID is allowed. Close/shutdown invalidate pending admission, and commit checks its token and current origin before replacing a live session. External preparation runs outside the session map; local PTY installation remains serialized. UTF-8 bounds and closing gates protect the lifecycle (`src-tauri/src/terminal_session.rs:358`, `src-tauri/src/terminal_session.rs:389`, `src-tauri/src/terminal_session.rs:662`, `src-tauri/src/terminal_session.rs:800`). SQLite history stores kind/target, not transcript; output uses IPC Channel, never HTTP terminal routes (`src-tauri/src/commands/terminal.rs:22`, `src-tauri/src/commands/terminal.rs:41`, `src-tauri/src/terminal_session.rs:106`, `src-tauri/src/terminal_session.rs:285`, `src-tauri/src/terminal_session.rs:486`, `src-tauri/src/terminal_session.rs:608`, `src-tauri/src/windows_pty.rs:156`, `src/lib/terminal-transport.ts:96`). |
| Metric sample | Collector owns timestamped instance/container attribution. SSE is lossy display; direct writer is an optional sink with no production registration found (`src-tauri/src/commands/metrics_collector.rs:118`, `src-tauri/src/commands/metrics_collector.rs:151`, `src-tauri/src/commands/metrics_collector.rs:557`). |
| Self-heal rule/firing | Row ID plus unique trigger; trigger/action are fixed while mode, threshold, quota and enabled can change. Suggest is default. Advisory actions remain Suggest; kill switch precedes mode, original-generation/host validation, quota and action. Raw events carry original generation before debounce, and recovery clears counting state (`src-tauri/src/commands/self_heal.rs:607`, `src-tauri/src/commands/self_heal.rs:679`, `src-tauri/src/docker_state.rs:224`). Executed/Failed spend per-rule hourly quota; blocked/advice outcomes do not (`src-tauri/src/commands/self_heal.rs:110`, `src-tauri/src/commands/self_heal.rs:240`, `src-tauri/src/commands/self_heal.rs:276`, `src-tauri/src/commands/self_heal.rs:360`, `src-tauri/src/commands/self_heal.rs:429`, `src-tauri/src/commands/self_heal.rs:607`). |
| Activity action | Stable target identity differs from display name; actor distinguishes User/App and outcome distinguishes success/failure/denial/cancellation. Best-effort recording redacts detail and cannot fail the original action (`src-tauri/src/commands/activity.rs:96`, `src-tauri/src/commands/activity.rs:120`, `src-tauri/src/commands/activity.rs:163`, `src-tauri/src/commands/activity.rs:376`, `src-tauri/src/commands/activity.rs:395`). |

Trigger metadata is not proof a detector runs: VM-unresponsive metadata has no observed firing producer; DiskFull uses reclaimable-byte heuristics. The self-heal gate/log path does not establish atomic concurrent quota reservation (`src-tauri/src/commands/self_heal.rs:351`, `src-tauri/src/commands/self_heal.rs:564`, `src-tauri/src/commands/self_heal.rs:607`, `src-tauri/src/commands/self_heal.rs:965`).

## Representations and boundary flows

DockerState caches daemon reads, republishes after reconnect and clears stale state on verified daemon loss. Colima instance display comes from the shared filesystem/status reader, honoring COLIMA_HOME; config GiB values become byte values in the response. Desktop poller and SSE publisher derive separate views from that same reader (`src-tauri/src/docker_state.rs:198`, `src-tauri/src/docker_state.rs:306`, `src-tauri/src/instance_reader.rs:50`, `src-tauri/src/instance_reader.rs:98`, `src-tauri/src/poller.rs:47`, `src-tauri/src/sse.rs:263`).

Frontend stores hold display copies. API list mapping and pushed-state normalization are separate paths; graph/list navigation converts resource identity before handoff. Read `docs/frontend-patterns-reference.md` when changing those mappings and `docs/topology-design-philosophy.md` when changing graph interactions (`src/lib/api/docker.ts:7`, `src/lib/dataPoller.ts:167`, `src/lib/normalizers.ts:12`, `src/lib/topology-link.ts:23`).

Transfer events are fast updates; registry list is the recovery authority after reload/stream gaps. If a terminal outcome has expired, the UI marks it ended/unknown rather than inventing success. Canonical destination claims conservatively reject Windows case aliases within the process; no cross-process destination lock is claimed (`src/lib/transferNotifications.ts:62`, `src-tauri/src/validation.rs:208`, `src-tauri/src/transfer_registry.rs:128`).

File-output transfers and SBOM acquire the same process-local destination claim before child/scanner acquisition. A per-job gate orders accepted cancellation, publication and the first terminal outcome; filesystem I/O runs without holding the registry map lock. UI/HTTP cancellation arriving during publication is refused as finishing, rather than reported accepted. Successful publication settles Success before a later cancellation can change it. Exclusive scratch and caller-owned replace/no-replace permission preserve an existing destination when cancellation wins (`src-tauri/src/transfer_registry.rs:128`, `src-tauri/src/transfer_registry.rs:259`, `src-tauri/src/transfer_registry.rs:445`, `src-tauri/src/transfer_registry.rs:223`, `src-tauri/src/streaming_cmd.rs:441`, `src-tauri/src/commands/file_transfer.rs:40`, `src-tauri/src/commands/security_scan.rs:615`).

HTTP and native wrappers can differ in state cleanup/activity side effects: HTTP Colima stop/delete are CLI-only, and HTTP self-heal configuration calls raw data functions while desktop wrappers also record activity. Read the caller, not just a shared type or operation name (`src-tauri/src/routes/instances.rs:28`, `src-tauri/src/commands/colima.rs:330`, `src-tauri/src/routes/self_heal.rs:32`, `src-tauri/src/commands/self_heal.rs:1028`).

Quit closes session acquisition, cancels queued/running jobs and waits for output/process settlement before closing the private reference. A 10 second timeout keeps the app open and emits localized shutdown recovery. Explicit engine restart separately admits cleanup before requesting restart; refusing active transfers leaves admission/work available (`src-tauri/src/lib.rs:404`, `src/lib/dataPoller.ts:257`, `src-tauri/src/commands/engine_connection.rs:72`, `src-tauri/src/transfer_registry.rs:184`). Closing a session/app acquires no external engine/container lifecycle; native qualification remains pending.

Windows host capability is an authority boundary, independent of installed tools. VM/Kubernetes/runtime-install families refuse at backend command/adapter/raw-route owners; frontend availability gates admission and presentation only. On Windows, ordinary resource displays require current run/revision/origin generation plus complete current membership before view admission and one-shot recovery. C/I provenance and full-read completeness are separate display facts; retained terminal sessions keep their own origin and ended state (`src-tauri/src/host_features.rs:5`, `src-tauri/src/host_features.rs:74`, `src/lib/dataPoller.ts:167`, `src/App.svelte:230`).

Recovery snapshots are App-lifetime input and neutral view intent, separate from resource/terminal/job ownership. Scope is one active page and original context/endpoint/engine; revision replacement restores once, while navigation/origin change/disposal discards them. Checked/detail identities bind to fresh resources, graph/samples/projects; Security checks content ID plus reference. Recovered image exports require every original content-ID/reference pair in the fresh list; the nested dialog restores paths/overwrite only for the same mode/container/reference/content signature. Export requests still use ordinary references, so this recovery check does not freeze mutable tags (`src/pages/Images.svelte:34`, `src/pages/Images.svelte:251`, `src/components/transfer/TransferDialog.svelte:52`, `src/components/transfer/TransferDialog.svelte:176`). Old results and effect/approval authority are excluded; no new entity, persistence or runtime authority is introduced (`src/lib/recoveryDrafts.svelte.ts:17`, `src/pages/Containers.svelte:504`, `src/pages/Activity.svelte:55`, `src/pages/Security.svelte:67`).

SAFE assistant configuration status crosses into the next model-request history. Its handler exposes only a known provider identifier (or unknown) and model/key/endpoint presence; failed reads return fixed unknown-status text. Stored credentials, private endpoint/model text and unrelated settings stay out of this result, including inactive-provider values. The selected credential still authenticates the provider connection separately; settings storage and NORMAL update authority are unchanged (`src/lib/aiEvents/config.ts:47`, `src/lib/aiEventBus.ts:38`, `src/lib/agentCore.ts:101`, `src/lib/agentCore.ts:153`, `src/lib/agentCore.ts:346`; `docs/specs/windows-docker-ui.md` BR-WINUI-05/TC-WINUI-016).

## Persisted choices and relationships

The shared `knowledge.db` connection supports diagnostic knowledge, settings/presets, chat, articles, terminal metadata and self-heal. `activity.db` independently owns action history. Relationships below are enforced by application code unless a schema constraint is cited; do not infer SQL foreign keys (`src-tauri/src/commands/knowledge_bank.rs:7`, `src-tauri/src/commands/knowledge_bank.rs:27`, `src-tauri/src/commands/self_heal.rs:263`, `src-tauri/src/commands/activity.rs:292`).

| Persisted concept | Behavior and owner |
| --- | --- |
| Solutions and memories | Solutions have integer identity/feedback counters and form short diagnostic context. Memories have text identity and FTS search maintained by schema triggers (`src-tauri/src/commands/knowledge_bank.rs:164`, `src-tauri/src/commands/knowledge_bank.rs:449`, `src-tauri/src/commands/knowledge_bank.rs:578`, `src-tauri/src/commands/knowledge_bank.rs:666`). |
| Offline Help article | Separate from solutions; unique `(slug, locale)`, locale normalization/English fallback, replacement only when shipped version increases (`src-tauri/src/commands/knowledge_bank.rs:127`, `src-tauri/src/commands/kb_articles.rs:153`, `src-tauri/src/commands/kb_articles.rs:169`, `src-tauri/src/commands/kb_articles.rs:208`). |
| Chat thread/message | Text IDs; missing conversation uses default. Save ensures parent, upserts message and updates recency. Deletes are conversation-scoped; default thread is retained. Locking serializes local access but save/delete are not multi-statement transactions (`src-tauri/src/commands/ai_chat.rs:123`, `src-tauri/src/commands/ai_chat.rs:146`, `src-tauri/src/commands/ai_chat.rs:183`, `src-tauri/src/commands/ai_chat.rs:203`). |
| Settings/preset/snapshot | Settings upsert strings by key; presets store opaque JSON by caller ID. Snapshots associate saved JSON with preset/profile/time, rather than owning current engine state (`src-tauri/src/commands/knowledge_bank.rs:821`, `src-tauri/src/commands/knowledge_bank.rs:950`, `src-tauri/src/commands/knowledge_bank.rs:1003`). |
| Heal/action timeline | Heal log links rule/resource identity in application code; activity feed combines it with independent action history and exposes failed sources through `partial`. A timeline is evidence about actions, not current runtime authority (`src-tauri/src/commands/self_heal.rs:287`, `src-tauri/src/commands/activity_feed.rs:140`). |

Colima configuration remains an external tool-owned YAML document: edit managed fields while retaining unknown keys and refusing stale mtime. Security scan results are a digest-keyed process cache; Trivy owns its DB and SBOM is an export, not persisted audit history (`src-tauri/src/commands/colima_config.rs:605`, `src-tauri/src/commands/security_scan.rs:285`, `src-tauri/src/commands/security_scan.rs:455`, `src-tauri/src/commands/security_scan.rs:591`).

Read `docs/backend-patterns-reference.md` for request/storage/async contracts and `docs/seed-test-data-reference.md` for fixture/startup-content ownership. Preserve the distinction between runtime authority, application choices, transient job state and historical observations.
