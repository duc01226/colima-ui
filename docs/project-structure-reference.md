# Project structure and execution

> Last scanned: 2026-10-14

Read this before planning cross-module changes, locating executable entry points or choosing build/runtime prerequisites. The repository has one frontend package and one shared Rust application crate; source directories do not establish independently deployed services.

## Runtime and external boundaries

Ordinary UI operations select IPC or localhost HTTP through the shared API client. Dashboard push uses Tauri events or browser SSE; metrics use SSE in both modes. Interactive terminals use native IPC Channel/PTY, including ContainerExec, and have no HTTP terminal-session surface; sandbox execution routes remain separate. Frontend AI streaming can call provider endpoints directly through browser/Tauri-plugin fetch, separately from local resource APIs (`src/lib/api/client.ts:112`, `src/lib/dataPoller.ts:218`, `src/lib/api/metrics.ts:65`, `src/lib/terminal-transport.ts:96`, `src-tauri/src/api_server.rs:341`, `src-tauri/src/api_server.rs:351`, `src/lib/llmProviders.ts:20`).

Docker/nerdctl, Colima, Lima and Kubernetes operations cross local process/daemon boundaries. POSIX runtime helpers resolve active profile/runtime and PATH; Windows resolves one captured connection. Service adapters are also used by CLI/self-heal. Knowledge-bank SQLite and independent activity SQLite store application choices/history; DockerState caches external live state. Transfer registry and streaming child-process registry are separate in-memory owners (`src-tauri/src/commands/runtime.rs:3`, `src-tauri/src/services/container.rs:9`, `src-tauri/src/commands/knowledge_bank.rs:19`, `src-tauri/src/commands/activity.rs:292`, `src-tauri/src/docker_state.rs:188`, `src-tauri/src/transfer_registry.rs:1`).

Vite fixes port 1420 with strict-port behavior; optional TAURI_DEV_HOST changes host/HMR configuration, whose port is 1421. Tauri dev uses that URL; build consumes `../dist`. The API binds an available localhost port in 11420–11429. Native consumers resolve only the actual bound port via IPC; browser development retains health discovery, and `cui` retains the private selected-instance reference (`vite.config.ts:43`, `src-tauri/tauri.conf.json:8`, `src-tauri/src/api_server.rs:34`, `src/lib/api/client.ts:45`, `src-tauri/src/api_reference.rs:68`).

Windows connection ownership lives in `engine_connection`: captured context/pipe/executable/config, original Linux daemon identity and availability generation remain process-local. `commands/engine_connection` exposes active/check/save/restart; save remains next-launch input, and explicit restart admits and settles work before request. `host_features` guards unsupported command/adapter/tool/HTTP paths; capability metadata and one shared UI form govern setup/navigation/recovery without granting backend authority (`src-tauri/src/engine_connection.rs:20`, `src-tauri/src/commands/engine_connection.rs:16`, `src-tauri/src/commands/engine_connection.rs:72`, `src-tauri/src/host_features.rs:5`, `src/components/settings/EngineConnectionSettings.svelte:65`). Generic child, stream, scratch/publication and ConPTY ownership retain their existing boundaries; native support and final whole-app proof remain pending.

Windows assistance uses the embedded Docker brief at native app-context acquisition, the filtered frontend event catalog and legacy-query capability gates. Safe-only command SSE and generation-fenced self-heal retain approval/kill-switch/quota rules. On Windows, App/data poller admit ordinary resources only with current host/ready/origin state and a complete four-family read for that generation, while Terminal retains its own C/I provenance and lifetime. On macOS/Linux, Docker failures leave VM recovery views available; the native POSIX/browser poller publishes successful groups independently with run/revision checks (`src-tauri/src/commands/system.rs:585`, `src/lib/agentCore.ts:77`, `src-tauri/src/routes/kb.rs:98`, `src-tauri/src/commands/self_heal.rs:679`, `src/App.svelte:80`, `src/lib/dataPoller.ts:28`).

Recovery ownership is `src/lib/recoveryDrafts.svelte.ts`: App supplies one active-page/original-origin scope. Resource pages/TransferDialog select unsent fields; resource/Topology/Activity/Compose/Security pages also register neutral selection/filter/tab choices and freshly bind identities. Activity/Security lift nested preferences through ordinary bound props. Retained Terminal and backend job/resource authority remain separate (`src/lib/recoveryDrafts.svelte.ts:17`, `src/App.svelte:86`, `src/pages/Activity.svelte:55`, `src/pages/Security.svelte:449`).

Read `docs/backend-patterns-reference.md` for request/storage/background owners, `docs/frontend-patterns-reference.md` for state/navigation, and `docs/domain-entities-reference.md` for resource identities and invariants.

## Build, quality and delivery

Use `npm run dev` for Vite, `npm run tauri dev` for native development, `npm run build` for frontend output and `npm run tauri build` for desktop bundles. Native prerequisites must match the host. Windows candidate/signed builds use a per-user NSIS/WebView2 overlay and write artifact/tool/source receipts; signed mode verifies actual Authenticode app/installer and updater artifacts. These separate dispatch workflows do not publish a Windows release or establish Windows 11/provider qualification (`package.json:26`, `scripts/windows-build.mjs:9`, `src-tauri/tauri.windows.conf.json:7`, `.github/workflows/windows-candidate.yml:4`).

Package prepare uses the platform-neutral `node scripts/setup-hooks.mjs` runner and literal Git argv; the installed hooks remain POSIX shell scripts, requiring Git for Windows on native Windows (`package.json:23`, `scripts/setup-hooks.mjs:1`, `scripts/setup-hooks.mjs:9`, `scripts/setup-hooks.mjs:16`).

CI frontend gates run on Ubuntu. Rust locked all-target/all-feature check/Clippy covers macOS/Linux/hosted Windows MSVC; native macOS, Linux and Windows lanes run library tests, while the macOS cross lane does not. These lanes do not select ignored live-provider tests. Dedicated Windows 11 qualification is separately dispatched to a prepared self-hosted runner (`.github/workflows/ci.yml:63`, `.github/workflows/ci.yml:143`, `.github/workflows/windows-qualification.yml:4`). Read `docs/code-review-rules.md`, `docs/integration-test-reference.md` and `docs/windows-qualification.md` before selecting gates or native evidence.

Manual promotion creates dev→staging or staging→main PRs. Version tags select beta/RC/stable releases; stable requires main ancestry, RC staging ancestry only warns, beta has no branch restriction. Release asset checks warn without failing, so they do not prove artifact readiness. No rollback contract was established from these owners (`.github/workflows/promote.yml:6`, `.github/workflows/release.yml:33`, `.github/workflows/release.yml:66`, `.github/workflows/release.yml:199`).

Read `scripts/release.sh` only when preparing authorized publication: it changes versions, commits, tags and pushes. Updater settings belong to Tauri config; CI signing uses GitHub secret references, including TAURI_SIGNING_PRIVATE_KEY and optional Apple signing/notarization references. Record names/mechanisms, never values (`scripts/release.sh:29`, `scripts/release.sh:72`, `src-tauri/tauri.conf.json:46`, `.github/workflows/release.yml:144`).

## Configuration and readiness

`path_util` owns native PATH split/join and executable discovery. Windows desktop/standalone CLI share absolute `.exe` lookup, including an existing Rancher `.rd/bin` under the native profile; POSIX retains shell/PATH augmentation and Colima socket discovery. Windows SDK/CLI paths use the resolved connection’s controlled environment rather than rediscovering ambient Docker selectors (`src-tauri/src/path_util.rs:102`, `src-tauri/src/path_util.rs:240`, `src-tauri/src/path_util.rs:285`, `src-tauri/src/engine_connection.rs:55`, `src-tauri/src/engine_connection.rs:61`).

App and CLI share `try_app_data_dir`: Windows native KnownFolder LocalAppData plus `ColimaUI`; macOS/Linux nonempty HOME or `/tmp`, plus `.colima-ui`. `windows_host` owns fallible native CPU/memory/disk probes; startup resolves storage before opening databases, and crash storage also handles resolution failure (`src-tauri/src/path_util.rs:76`, `src-tauri/src/windows_host.rs:38`, `src-tauri/src/windows_host.rs:47`, `src-tauri/src/commands/system.rs:413`, `src-tauri/src/lib.rs:125`, `src-tauri/src/crash.rs:65`). Exports and OS login items have separate owners.

`api_reference` stores a nonsecret selected-instance marker in existing settings and a private per-instance port/credential file. `private_file` establishes owner-only access before bytes and verifies the opened handle; failed publication does not select an older app, and exit removes only its own record. Browser auth still consumes an out-of-band fragment credential; native gets it via IPC. Keep credential content out of docs/evidence (`src-tauri/src/api_reference.rs:93`, `src-tauri/src/api_reference.rs:108`, `src-tauri/src/api_reference.rs:125`, `src-tauri/src/private_file.rs:8`, `src/lib/api/client.ts:188`, `src/lib/api/client.ts:203`).

Quit waits for terminal/transfer/stream/child settlement before closing its private API reference. Cleanup timeout prevents exit and emits localized `shutdown-blocked` recovery. Explicit engine restart separately performs atomic transfer admission and cleanup before requesting restart; native outcomes remain pending (`src-tauri/src/lib.rs:404`, `src-tauri/src/commands/engine_connection.rs:72`, `src-tauri/src/transfer_registry.rs:184`, `src/lib/dataPoller.ts:257`).

API port exhaustion logs API-disabled rather than aborting the desktop process. Health proves liveness/discovery, not Docker/Colima readiness. Resource capabilities and actual operation prerequisites must be checked separately (`src-tauri/src/api_server.rs:459`, `src-tauri/src/routes/system.rs:140`, `src/store/capabilities.svelte.ts:63`). Read `README.md` for setup, and `docs/telemetry.md` before changing outbound data.
