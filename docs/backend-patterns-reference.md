# Backend patterns

> Last scanned: 2026-10-14

Read this before changing Rust requests, validation, storage or background work. Trace the actual entry point and consumer: desktop IPC, HTTP and standalone CLI share some owners but have different side effects. This guide records source behavior; it does not establish runtime verification.

## Request and rule ownership

HTTP registration lives in `src-tauri/src/api_server.rs:66`; native registration in `src-tauri/src/lib.rs:173`. Container routes usually extract input and delegate to commands, where shared exec/run checks live. Kubernetes also has direct route-owned CLI logic. CLI and self-heal use service/adapter paths, while GUI commands can use runtime helpers directly; there is no universal commands → services → adapters pipeline (`src-tauri/src/routes/containers.rs:23`, `src-tauri/src/commands/containers.rs:839`, `src-tauri/src/routes/k8s.rs:15`, `src-tauri/src/bin/cli.rs:274`, `src-tauri/src/commands/self_heal.rs:723`).

Trace variants before moving a rule. HTTP Colima stop/delete call CLI-only functions; desktop variants additionally clear/suppress Docker state, emit events and record activity. HTTP container listing uses CLI; native listing tries Bollard then falls back (`src-tauri/src/routes/instances.rs:28`, `src-tauri/src/commands/colima.rs:258`, `src-tauri/src/commands/colima.rs:330`, `src-tauri/src/routes/containers.rs:11`, `src-tauri/src/commands/containers.rs:179`).

| Boundary | Owner and action-changing contract |
| --- | --- |
| Errors | `ColimaError` has stable snake_case codes and redacted technical context; frontend owns localization. Preserve known command/exit context with `error_from_output` where process output is available (`src-tauri/src/error.rs:22`, `src-tauri/src/error.rs:35`, `src-tauri/src/error.rs:60`, `src-tauri/src/helpers.rs:62`). |
| HTTP responses | Ordinary handlers use `ApiResponse<T>`; `err` currently returns 500 even for validation. Auth rejection is bare 401. Stream/SSE endpoints have separate contracts; stringifying a known error can lose optional context (`src-tauri/src/helpers.rs:21`, `src-tauri/src/helpers.rs:43`, `src-tauri/src/auth.rs:153`, `src-tauri/src/routes/instances.rs:23`). |
| HTTP auth | Health is public; operation router has auth middleware. Bearer is normal; query-token auth is explicitly allowlisted for events and pod log streams. Desktop token handoff is IPC; browser consumes an out-of-band URL fragment. There is no HTTP token endpoint (`src-tauri/src/api_server.rs:356`, `src-tauri/src/api_server.rs:366`, `src-tauri/src/auth.rs:49`, `src-tauri/src/auth.rs:74`, `src/lib/api/client.ts:223`). |
| CLI credential handoff | `api_reference` supersedes the nonsecret instance marker in existing settings before bind and publishes only that instance’s owner-private port/credential file after bind. `cui` uses the shared data root and read-only settings reader; missing/invalid/unavailable references never trigger a health-port fallback. Close removes only the instance’s own record and prevents later publication (`src-tauri/src/api_reference.rs:72`, `src-tauri/src/api_reference.rs:93`, `src-tauri/src/api_reference.rs:108`, `src-tauri/src/api_reference.rs:125`, `src-tauri/src/api_server.rs:417`, `src-tauri/src/bin/cui.rs:97`). |
| Windows engine origin | A resolved connection captures context/local pipe/executable/config; saved preferences are next-launch input. Use its controlled CLI environment/global argv and verified SDK client. Require the original Linux daemon ID; order overlapping checks and reject reads from an older availability generation (`src-tauri/src/engine_connection.rs:20`, `src-tauri/src/engine_connection.rs:55`, `src-tauri/src/engine_connection.rs:136`, `src-tauri/src/engine_connection.rs:194`, `src-tauri/src/engine_connection.rs:354`, `src-tauri/src/engine_connection.rs:465`). |
| Names and paths | Reuse profile/resource guards, including empty profile meaning default where `ensure_valid_profile` is used. Host writes use caller-selected-base `assert_path_within`, resolving existing paths or parents and failing closed; container-side paths use separate policy (`src-tauri/src/validation.rs:125`, `src-tauri/src/validation.rs:167`, `src-tauri/src/validation.rs:279`, `src-tauri/src/validation.rs:303`). |
| Typed exec and run | Shared exec checks ID and command text; run checks banned Docker flags/root-bind forms before execution and records environment counts rather than values. Literal lifecycle argv and separate adapters do not automatically inherit these checks (`src-tauri/src/commands/containers.rs:839`, `src-tauri/src/commands/containers.rs:904`, `src-tauri/src/commands/containers.rs:921`, `src-tauri/src/commands/containers.rs:978`). |

Sandbox classification is a separate policy owner. Safe/approved execution reclassifies; approval never permits Banned. Windows text execution permits only supported literal Docker argv through the captured target and bounded child owner. `execute_stream` carries no interactive approval grant: it invokes the safe executor and sends completed bounded stdout/stderr/exit or a redacted error, rather than incremental terminal output (`src-tauri/src/commands/shell_sandbox.rs:261`, `src-tauri/src/commands/shell_sandbox.rs:289`, `src-tauri/src/routes/kb.rs:98`). Read `docs/ai.md` when changing AI tool/approval behavior.

`host_features` is the application policy owner for native VM/Kubernetes/runtime-install refusal. Commands/adapters and `helpers::build_cmd` guard effects; authenticated raw HTTP routes also pass the feature guard, which returns 501 for unsupported families after auth. Metadata/UI hiding cannot grant authority (`src-tauri/src/host_features.rs:29`, `src-tauri/src/host_features.rs:74`, `src-tauri/src/helpers.rs:106`, `src-tauri/src/api_server.rs:366`).

## Storage and schema evolution

Activity’s `with_db` uses real in-memory SQLite and the production schema only in `cfg(test)` library builds. Its lazy connection remains process-local; calls through real `record` do not open or prune account history there. Non-test library builds retain the account `activity.db` path, including installed/integration consumers; their persistence/isolation needs separate arrangement and proof (`src-tauri/src/commands/activity.rs:352`, `src-tauri/src/commands/activity.rs:306`, `src-tauri/src/commands/activity.rs:527`).

Most persistence uses owner-local `rusqlite` SQL. `app_settings` centralizes the existing settings-row read/upsert for desktop, CLI/private-reference and engine-preference consumers; a missing row stays distinct from a SQL/decoding failure (`src-tauri/src/app_settings.rs:6`, `src-tauri/src/app_settings.rs:15`, `src-tauri/src/commands/knowledge_bank.rs:953`, `src-tauri/src/api_reference.rs:78`, `src-tauri/src/engine_connection.rs:259`). Knowledge-bank setup installs a mutex-protected `knowledge.db` connection before API/background work; chat, settings/presets, articles, terminal metadata and self-heal share it. Activity owns a separate lazily opened `activity.db` (`src-tauri/src/lib.rs:125`, `src-tauri/src/commands/knowledge_bank.rs:7`, `src-tauri/src/commands/self_heal.rs:263`, `src-tauri/src/commands/activity.rs:292`).

Schema setup uses owner-local idempotent DDL. Chat's guarded migration adds conversation identity and adopts retained history; schema triggers maintain memory/article FTS indexes. A connection lock does not make multiple SQL statements transactional: chat save/delete are sequential under a guard, while activity retention commits its age/count deletes in one transaction (`src-tauri/src/commands/knowledge_bank.rs:148`, `src-tauri/src/commands/knowledge_bank.rs:216`, `src-tauri/src/commands/ai_chat.rs:123`, `src-tauri/src/commands/ai_chat.rs:183`, `src-tauri/src/commands/activity.rs:424`).

Read `src-tauri/src/commands/knowledge_bank.rs` when evolving shared schema/settings/presets; read `src-tauri/src/commands/ai_chat.rs` for thread behavior and `src-tauri/src/commands/kb_articles.rs` for offline Help/search. Article replacement is gated by a greater shipped version; read `docs/seed-test-data-reference.md` before changing startup content (`src-tauri/src/commands/kb_articles.rs:169`).

Record machine actions through `activity::record`. Its owner redacts detail, tolerates storage failure and opportunistically prunes to 7 days/500 rows after writes; these are periodic pruning bounds, not an immediate cap. Live engine/VM state remains external authority. Exports, Colima files and autostart have separate location owners (`src-tauri/src/commands/activity.rs:375`, `src-tauri/src/commands/activity.rs:382`, `src-tauri/src/commands/activity.rs:395`, `src-tauri/src/commands/activity.rs:424`, `src-tauri/src/commands/autostart.rs:26`).

Use `path_util::try_app_data_dir` for fallible app/CLI data resolution: Windows KnownFolder LocalAppData plus `ColimaUI`; macOS/Linux nonempty HOME or `/tmp`, plus `.colima-ui`. Startup resolves the directory before opening storage. Native PATH uses split/join; Windows `.exe` discovery uses absolute search directories. Windows host-probe errors propagate through IPC/HTTP, diagnostics and config callers; crash storage is also fallible (`src-tauri/src/path_util.rs:76`, `src-tauri/src/path_util.rs:102`, `src-tauri/src/path_util.rs:240`, `src-tauri/src/windows_host.rs:38`, `src-tauri/src/lib.rs:125`, `src-tauri/src/commands/system.rs:413`, `src-tauri/src/routes/system.rs:68`, `src-tauri/src/commands/diagnostics.rs:155`, `src-tauri/src/commands/colima_config.rs:589`, `src-tauri/src/crash.rs:65`).

Private references use `private_file`: create owner-only access before writing, verify the opened handle before reading, and remove a failed write. Unix requires current ownership, no group/other access and one link; Windows requires a protected current-account DACL and refuses reparse points/extra links. Do not put the credential in ordinary settings or diagnostic evidence. Native Windows permissions still require qualification (`src-tauri/src/private_file.rs:8`, `src-tauri/src/private_file.rs:20`, `src-tauri/src/private_file.rs:48`, `src-tauri/src/private_file.rs:159`, `src-tauri/src/private_file.rs:225`).

Security findings use a digest-keyed process cache with a 6-hour TTL; Trivy owns its vulnerability database. Colima YAML editing preserves unmanaged keys, checks expected mtime, backs up and fsyncs/renames a sibling temporary file. File-output transfers and SBOM publish scratch output under explicit replace/no-replace policy; activity/diagnostic exports use direct writes, so choose the actual owner's contract (`src-tauri/src/commands/security_scan.rs:285`, `src-tauri/src/commands/security_scan.rs:455`, `src-tauri/src/commands/security_scan.rs:615`, `src-tauri/src/streaming_cmd.rs:441`, `src-tauri/src/commands/colima_config.rs:508`, `src-tauri/src/commands/colima_config.rs:605`, `src-tauri/src/commands/activity_feed.rs:289`, `src-tauri/src/commands/diagnostics.rs:443`).

## Background work and delivery

Interactive acquisition uses `create_shared_session`: reserve one ID briefly, run daemon/tool/config preparation on a blocking worker outside the shared session map, then verify the reservation and Windows origin before local PTY installation/replacement. The cap16 counts live-or-opening IDs; a reconnect shares its live slot and only one opening per ID is admitted. Close/shutdown cancels pending tokens; a stale worker cannot install later. Preparation failure leaves a prior live session intact; later PTY-spawn failure has a different boundary (`src-tauri/src/terminal_session.rs:358`, `src-tauri/src/terminal_session.rs:389`, `src-tauri/src/terminal_session.rs:662`, `src-tauri/src/terminal_session.rs:800`, `src-tauri/src/commands/terminal.rs:67`).

DockerState owns the single daemon event stream, reconnect and cache invalidation; SSE consumes raw events. Native/SSE projections share `fetch_resources`, where either SDK list failure remains an error rather than an empty engine. Windows snapshots retain availability-generation guards (`src-tauri/src/docker_state.rs:424`, `src-tauri/src/docker_state.rs:466`, `src-tauri/src/sse.rs:151`, `src-tauri/src/sse.rs:212`). Raw lifecycle publication precedes display debounce so self-heal can count individual events. The raw broadcast has capacity 512 and can lag; SSE display has capacity 64, reports `stream-lagged` and has no replay (`src-tauri/src/docker_state.rs:232`, `src-tauri/src/docker_events.rs:33`, `src-tauri/src/docker_events.rs:78`, `src-tauri/src/sse.rs:6`, `src-tauri/src/routes/misc.rs:83`).

Dashboard state uses desktop events or browser SSE; metrics use named-topic SSE in both modes. Explicit `metrics.sample` subscriptions activate the collector; topicless SSE clients do not. Optional `MetricWriter` receives batches before display publication, but no production writer registration was found. CPU baselines include origin/recovery generation while retaining the display instance (`src-tauri/src/commands/metrics_collector.rs:372`, `src-tauri/src/commands/metrics_collector.rs:420`). Enabled POSIX resource-saver polling is independent of collector gating; the Windows external-VM daemon does not start (`src/lib/dataPoller.ts:218`, `src/lib/api/metrics.ts:65`, `src-tauri/src/sse.rs:62`, `src-tauri/src/commands/metrics_collector.rs:155`, `src-tauri/src/commands/system.rs:680`).

Keep recovery appropriate to the data: state consumers refetch; chart consumers show gaps; transfer consumers reconcile against registry snapshots (`src-tauri/src/sse.rs:154`, `src/lib/api/metrics.ts:104`, `src/pages/Activity.svelte:77`, `src/lib/transferNotifications.ts:62`).

| Long-lived owner | Contract |
| --- | --- |
| Transfers | `transfer_registry` owns job/outcome and process-local destination claims; `streaming_cmd` owns generic child/scratch/publication. Sources and destination parents are canonical; Windows claims conservatively reject case aliases. Revalidate queued origin, record cancel before spawn/kill and settle only after consumer/output cleanup. File-output success follows publication, with explicit replace versus no-replace policy; other jobs require successful runtime completion. Terminal outcomes remain for 60 seconds; no cross-process destination lock is claimed (`src-tauri/src/commands/file_transfer.rs:40`, `src-tauri/src/commands/file_transfer.rs:329`, `src-tauri/src/transfer_registry.rs:128`, `src-tauri/src/validation.rs:257`, `src-tauri/src/streaming_cmd.rs:441`). |
| Processes | Short and streaming execution share generic `ChildProcess` ownership: Unix groups or Windows Job assignment before execution. Weak tree registration and stopping gates refuse late children; capture, stderr and line/consumer queues are bounded. Stream registration survives through scratch/publication cleanup (`src-tauri/src/child_process.rs:49`, `src-tauri/src/child_process.rs:57`, `src-tauri/src/child_process.rs:86`, `src-tauri/src/streaming_cmd.rs:234`, `src-tauri/src/streaming_cmd.rs:329`, `src-tauri/src/streaming_cmd.rs:476`). |
| Interactive terminals | One SessionManager/IPC Channel lifecycle includes ContainerExec; target preflight and create require stable ID, original engine and running/nonpaused container. Windows uses ConPTY with atomic Job membership; other native target kinds refuse. Cap of 16, bounded UTF-8 output/carry, nonzero resize, origin-loss input fence and poll-exit release stay at that owner; closing refuses late acquisition. No HTTP terminal/host fallback (`src-tauri/src/commands/terminal.rs:22`, `src-tauri/src/terminal_session.rs:285`, `src-tauri/src/terminal_session.rs:486`, `src-tauri/src/terminal_session.rs:570`, `src-tauri/src/terminal_session.rs:608`, `src-tauri/src/terminal_session.rs:643`, `src-tauri/src/windows_pty.rs:156`). |
| Self-heal | Executor checks kill switch → Suggest/advisory → originating generation/host capability → quota → perform. Raw lifecycle generation is captured before debounce; counters reset on recovery and stale events cannot authorize actions. Executed/Failed alone spend quota; unreadable quota fails closed. This does not establish atomic concurrent quota reservation (`src-tauri/src/commands/self_heal.rs:607`, `src-tauri/src/commands/self_heal.rs:679`, `src-tauri/src/commands/self_heal.rs:827`, `src-tauri/src/docker_state.rs:224`). |

Quit closes terminals and cancels Starting/Running transfers, then waits for consumer/stream/child settlement; timeout prevents exit, emits `shutdown-blocked` and leaves private-reference close until successful cleanup. Explicit restart first calls atomic `begin_shutdown`: refusal with active work changes no admission state, while admitted shutdown refuses late registrations. Terminal outcomes are monotonic; cancelled/settled jobs cannot run again (`src-tauri/src/commands/engine_connection.rs:72`, `src-tauri/src/transfer_registry.rs:184`, `src-tauri/src/transfer_registry.rs:194`, `src-tauri/src/transfer_registry.rs:216`, `src/lib/dataPoller.ts:257`).

ConPTY keeps duplicate parent pipe ends in an owner declared after Master, so later acquisition errors close those ends before Master joins its output pump. Normal creation releases them at the existing success point. The native failed-launch parent/child guard authors three actual bad-executable failures under bounded capture, plus the existing normal-console control; no native execution is claimed (`src-tauri/src/windows_pty.rs:193`, `src-tauri/src/windows_pty.rs:542`).

Compose client locations retain file (`-f`) versus directory (`--project-directory`) meaning; Windows named-project actions resolve listed ConfigFiles and refuse malformed/unreadable metadata. POSIX project actions retain launch-directory behavior (`src-tauri/src/commands/compose.rs:211`, `src-tauri/src/commands/compose.rs:238`).

File-output transfers and SBOM acquire the same process-local destination claim before child/scanner acquisition. A per-job gate orders accepted cancellation, publication and the first terminal outcome; filesystem I/O runs without holding the registry map lock. UI/HTTP cancellation arriving during publication is refused as finishing, rather than reported accepted. Successful publication settles Success before a later cancellation can change it. Exclusive scratch and caller-owned replace/no-replace permission preserve an existing destination when cancellation wins (`src-tauri/src/transfer_registry.rs:128`, `src-tauri/src/transfer_registry.rs:259`, `src-tauri/src/transfer_registry.rs:445`, `src-tauri/src/transfer_registry.rs:223`, `src-tauri/src/streaming_cmd.rs:441`, `src-tauri/src/commands/file_transfer.rs:40`, `src-tauri/src/commands/security_scan.rs:615`).

Transfer SSE emission is unconditional; Tauri emission requires the initiating IPC AppHandle. Announcements use a fixed parameterless feed request; the client owns scheduling and checks the off switch first. Read `docs/telemetry.md` when changing outbound data (`src-tauri/src/commands/file_transfer.rs:73`, `src-tauri/src/commands/announcements.rs:95`, `src/lib/announcements.ts:268`).

Windows Trivy is optional: missing native executables fail resolution; its command owner revalidates the selected connection, applies the captured environment and limits local image sources to Docker (`src-tauri/src/commands/security_scan.rs:414`, `src-tauri/src/commands/security_scan.rs:420`). Existing connection-setting writers validate a checked selection before persistence; saving remains next-launch input (`src-tauri/src/commands/knowledge_bank.rs:961`). Native support and complete application proof remain pending; do not infer coverage from a shared builder.

Read `docs/domain-entities-reference.md` for identities and invariants, `docs/integration-test-reference.md` for boundary-test isolation, and `docs/code-review-rules.md` for review gates. Preserve transport-specific validation, transaction, delivery and cleanup contracts at their actual owners.

`GET /api/metrics/status` is an authenticated, read-only observer of existing collector/engine state. It does not initialize the engine, subscribe, start a tick or change the interval. It requires the normal Authorization header and adds no query-token exception (`src-tauri/src/api_server.rs:170`, `src-tauri/src/commands/metrics_collector.rs:94`, `src-tauri/src/auth.rs:49`).
